# Pilot：衝突與重派

[pilot.md](pilot.md) 的 pointer 指到這裡時才讀：`pilot-land.mjs` 印 `STOP conflict` 或 `RESOLVED`，或成員要重派（同一條目衝突、`WORKER <n> STOP findings after two review cycles`）。下文的 `<主 checkout>`、`<stage worktree>` 與其他條目名稱都指 pilot.md 與 [pilot-exceptions.md](pilot-exceptions.md) 的同名條目。

- **Stage conflict.** `pilot-land.mjs`（setup-workflow 正本的副本）的衝突只照下列解法自己解：`docs/agents/workflow-templates.json` 的 restamp 是正本自己做，其餘解法與流程站戳記由 Stage 指令的 `--resolver scripts/pilot-resolve.mjs` 提供（#245）。每解一次印 `RESOLVED <n> <解法> <檔案…>`，解完的 staged SHA 一樣要跑 Regression：衝突檔有戳記檔（`scripts/workflow-doc-sync.json`、`docs/agents/workflow-templates.json`；`land.mjs` 經 `scripts/restamp.mjs` 的 `STAMP_FILES` 認得同兩個）時（兩邊合併前都已各自對照 `docs/workflow/` 並 restamp），其他衝突檔先用下列解法解完，再依合併結果重算（和 `land.mjs` 用同一套重算）：`workflow-doc-sync.json` 重產站台後跑 `scripts/check-workflow-sync.mjs --restamp`（站台 `docs/workflow/site/**` 是 `build-workflow-site.mjs` 的產物，resolver 以 `isGenerated` 認得，衝突時和戳記檔一起取目標分支版本、重產，不另開 gate；只有站台與戳記檔衝突時印 `RESOLVED <n> restamp <檔案…>`，重產失敗照其他衝突 abort，#589），`workflow-templates.json` 取兩邊條目的聯集、依合併後的副本重算 sha256（`restamp`，#72、#173；和別的解法一起時 restamp 排最後，印成 `entries+restamp`、`rows+restamp` 這類組合）；每個衝突 hunk 的 base 都是空的、兩邊只是在同一處新增不重疊的段落時，依號碼兩段都留下（`additions`；兩邊各自新增同一個檔、新增的段落有相同的行或同名的條目都不算）；每個衝突 hunk 裡兩邊改的是不同的 `- **<名稱>.**` 條目時各取各的版本，兩邊改過的條目都留下（`entries`，#45）；衝突 hunk 的 base、ours、theirs 三份的行都是 Markdown 表格列（`|` 開頭）時，以第一格為鍵，兩邊改的是不同列就各取各的版本、依原順序排好，新增的列都留下（`rows`，#162；同一列兩邊都改時，欄數相同、第一格沒變，逐格合併，同一格兩邊都改的以 base 為準逐字三方合併，改動不重疊也不相鄰才合，否則仍是衝突；一邊刪一邊改、兩邊新增同一個鍵、某一份有重複的鍵、留下的列順序變了、各列欄數不同都仍是衝突）；衝突 hunk 裡一邊只改了 base 的某幾行、另一邊只在 base 行之間插入新行（沒改任何 base 行），插入點不在改動的那幾行中間時兩邊都套用（`adjacent`，#175：#131 改了 `pilot-close.mjs` 檔頭一行註解、#143 在那行後面插入兩行；一邊只刪掉 base 行（純刪除不算改動）、兩邊動到同一個 `- **<名稱>.**` 條目（同一條目衝突；插入的新條目切開另一邊正在改的條目也算）、兩邊都改了同一個 base 行、改動或插入碰到表格列（歸 `rows` 判斷）、兩邊的最短 diff 對齊不只一種而合出不同結果（重複行能滑動、拆段插入；hunk 前後各一行一起對齊，對齊動到 hunk 外那一行也算）、換上的行和插入的行相同（非空行或同名條目，合起來會重複）、碰到檔尾沒換行的行都仍是衝突，組合照樣印成 `adjacent+restamp` 這類）。`additions`、`entries`、`rows` 與 `adjacent` 只解三個版本都是 UTF-8 文字的檔案。其他衝突（包括戳記檔和解不了的檔一起衝突）它先 `merge --abort`，印 `STOP conflict <n> <檔>=<來源>:<種類> …`（每個衝突檔一項，#192；`sync-main` 的是 `STOP conflict sync-main <檔>=main:<種類> …`，來源固定是 `main`，見 pilot.md 的 **Integration branch.**，#589），stage worktree 是乾淨的：來源是 `member <m>`（本次 stage 依號碼先合入、自己的分支改過這個檔的同批成員）、`integration`（成員開分支之後整合分支改過）或以 + 相連的多個來源（`member <m>+integration`、`member <m>+member <k>`；都看不出來時是 `unknown`，不該發生，照其他衝突變成 gate）；種類是 `entry <名稱>`（Markdown 檔解不了的 hunk 裡兩邊都改的 `- **<名稱>.**` 條目，一邊增刪了條目、條目對不齊時是 hunk 碰到的每個條目，多個以、相連）、`code`（程式檔）或 `other`，例如 `STOP conflict 108 scripts/lib/hosts.mjs=member 79:code docs/agents/pilot.md=integration:entry Pool`。這時讀種類欄判斷是不是同一條目衝突（有檔的來源是 `unknown` 時不算，照其他衝突變成 gate），不再對兩邊跑 diff：至少一個檔是 `entry <名稱>`（skill 的同一條規則也是這種條目），其餘衝突檔只是同一處改動在 `docs/workflow/` 的轉述、產生的 html 與戳記檔。是的話不開 gate，照 Fresh redispatch 重派這個成員，帶上整併後的範圍（另一邊的改動照來源欄去看：`member <m>` 是那個成員的分支，`integration` 是整合分支），並照 Decisions 記一筆（衝突檔、prior 分支與 SHA）。來源含 `member <m>` 時照這個順序做，fresh worker 才從已含 #m 的整合分支開始（先重派的話 fresh worker 從 #m 合入前的整合分支開分支，做完一定再跟 #m 衝突、變成 `refresh-twice`，batch 79-108）：先跑 `node scripts/pilot-batch.mjs <主 checkout> move <key> <n> --state stop` 把它移出原 batch，再重跑 `node scripts/pilot-land.mjs <key> --check-command 'bin/check --upstream' --resolver scripts/pilot-resolve.mjs` 讓其餘成員合入整合分支，印 `MERGED` 之後才照 Fresh redispatch 跑 `node scripts/pilot-dispatch.mjs <n> --fresh <n>:<slug> --note <主 checkout>/.scratch/pilot/fresh-<n>.md`（key 是它自己的 `<n>`，就地改寫 `batch-<n>.md`）。來源只有 `integration`、而且 Probe 沒對它和同 batch 其他 done 成員印過 `OVERLAP <n> <m>` 時，照 Fresh redispatch 以原 key 重派，重派後原 batch 只剩其他成員，重跑 `pilot-land.mjs <key>` 合入它們；印過的話照上面來源含 `member <m>` 的順序做，以原 key 重派會讓 `--fresh` 的 overlap 檢查撞上 #m（#258：batch 240-244 的 #240 衝突只來自 `integration`，以原 key 重派印 `STOP 240 overlap 244 …`）。同一個 Issue 重派後又衝突時 `--fresh` 印 `STOP refresh-twice <n>`，這時才開 gate，預設選項是「再重派一次」（帶 `--again`）。衝突檔的來源全是同批 `member <m>`、種類是 `code` 或 `other`（沒有 `entry`）時也不等人：同樣照來源含 `member <m>` 的順序 move、讓其餘成員合入、再 fresh 重派（「怎麼整併」寫 #m 改了這幾個檔的什麼），照 Gates 先 `open` 再立刻 `resolve` 留紀錄、不通知，同 `refresh-twice` 的先例（#260：batch 245-246 的 #246 四個衝突檔都是 `member 245:other`）。衝突檔的來源全是 `integration`（沒有 `member <m>`、`unknown`）、種類是 `code` 或 `other` 時，先照下面「仍開 gate 等人」的例外清單逐項查（含那串 `git` 查詢），一項命中就開 gate、不重派，都沒命中才不等人，照 Fresh redispatch 重派這個成員，「怎麼整併」寫整合分支改了這幾個檔的什麼，以原 key 或先 move 的判斷和上面來源只有 `integration` 的同一條目衝突相同（同 batch 其他 done 成員和它印過 `OVERLAP <n> <m>` 時先 move、讓其餘成員合入再重派），照 Gates 先 `open` 再立刻 `resolve` 留紀錄、不通知（#560：G16–G33 這類 gate 的答案都是預設的 fresh 重派，人不在時一個 gate 擋一整晚）。多個 batch 都和整合分支衝突又互相 overlap 時，照 [pilot-exceptions.md](pilot-exceptions.md) 的 **Dispatch stops.** 依號碼一次只重派一張，其餘 `node scripts/pilot-batch.mjs <主 checkout> park <key> <n> --after <先做的那張> --fresh --reason <原因>`（`--fresh` 讓 Probe 之後印 `UNPARK_FRESH`、直接重派，不先 stage 撞同一個衝突）；重派後又衝突（`STOP refresh-twice <n>`）照上面的 refresh-twice 處理。下列情況仍開 gate 等人、不重派（上面來源全是 `integration` 的 `code`／`other` 重派前要先查完的例外清單）：整併有設計取捨（兩邊對同一行為做了不同決定，不是兩邊都留下就好）；衝突檔在整合分支那一邊有不是經 pilot 合入的改動（經 `sync-main` 從 `main` 帶進來的、人或別的 session 直接合進 `main` 或 `pilot/integration` 的改動；也可能藏在 stage 合併後面：成員分支合過 `main`、成員改了檔名，或整合 PR 合併後整合分支快轉、first-parent 只剩 PR 合併），依序查，`<base>` 是 `git -C <主 checkout> merge-base <分支> pilot/integration`：先用 `git -C <主 checkout> log --follow --name-status --format= <base>..pilot/integration -- <檔>` 取這個檔在整合分支那一邊用過的每個路徑（每行狀態欄之後的路徑，改名行 `R<相似度>` 的舊、新路徑都算，連同 `<檔>` 本身，去重；`--name-only` 只印改名後的路徑，`--follow` 在有合併的歷史上也可能在走到改名之前就略過舊路徑的 commit）；這些路徑在 `<base>` 都不存在（每個 `git -C <主 checkout> cat-file -e <base>:<路徑>` 都失敗，例如同一個 commit 改名又大改、git 認不出改名）時看不出來源，開 gate；`git -C <主 checkout> log --first-parent --format='%H %s' <base>..pilot/integration -- <路徑…>` 印出 `Merge branch '…' into pilot/stage-<key>`（成員與 `retro/` 請求分支的 stage 合併，`pilot/stage-sync-main` 不算）與 `Merge pull request #… from …/pilot/integration` 以外的行時開 gate；印出的每個 `Merge pull request #… from …/pilot/integration`（第一欄是它的 SHA，記作 `<PR>`）再用 `git -C <主 checkout> log --first-parent --format='%H %s' <base>..<PR>^2 -- <路徑…>` 往下查、同樣判斷（又印出 PR 合併就再往下；整合 PR 合併後整合分支快轉，直接改進整合分支的改動在 PR 合併的第二個 parent 底下）；`git -C <主 checkout> log --first-parent --format=%s main origin/main ^<base> -- <路徑…>` 印出 `Merge pull request #… from …/pilot/integration` 以外的行（本機 `main` 可能落後 `origin/main`，兩個都查；還沒帶進整合分支的也算，保守開 gate）也開 gate；要暫緩或放棄這張單。其他 `STOP conflict`（有檔的來源是 `unknown`，或同時有 `member <m>` 與 `integration` 的 `code`、`other`）照舊變成 gate。
