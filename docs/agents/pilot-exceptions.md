# Pilot：少見的分支

[pilot.md](pilot.md) 的 pointer 指到這裡時才讀，每條只在 pointer 寫的情況用到。下文的 `<主 checkout>`、`<stage worktree>` 與其他條目名稱都指 pilot.md 的同名條目。

- **Bare guard.** Orca 從 WSL 做 worktree 操作（create、rm 都會）時，可能把主 checkout `.git/config` 的 `core.bare` 改成 `true`，之後 `git status` 回 `must be run in a work tree`，stage、merge 全部失敗。在主 checkout 跑 `scripts/pilot-unbare.sh <主 checkout> <時機>`（時機如 `probe`、`dispatch #<n>`、`stage #<key>`、`close #<n>`）：是 bare 就執行 `git config core.bare false`、在 `.scratch/pilot/decisions.md` 的表格追加一列，並印出 `UNBARE <checkout>`；不是 bare 時不輸出。下列 Probe、Dispatch、Stage、Close 都只呼叫它。主 checkout 的工作樹還沒有這支腳本時（本機 `main` 落後 `origin/main`），改跑 `git -C <主 checkout> rev-parse --is-bare-repository`，印出 `true` 就執行 `git -C <主 checkout> config core.bare false`，再照 Decisions 記一列。

- **Permissions.** `.claude/settings.json` 的 `permissions.allow` 有三條，每條都是本 repo 的 wrapper（規則比對 `node scripts/<name>` 這個相對路徑）、只做 adapter 指定的步驟，auto mode 才不會擋成 External System Writes：`Bash(node scripts/gh-tracker.mjs:*)`，本 repo 的留言、label、關單、開單、sub-issue 與依賴都經這支（[issue-tracker.md](issue-tracker.md)，#96）；`Bash(node scripts/land.mjs:*)`，Push gate 與單獨跑的 `/issue-run` 落地時 push、開 PR、等 CI 通過後才合併（[Evidence and closing](issue-run.md#evidence-and-closing)）；`Bash(node scripts/pilot-close.mjs:*)`，Close 的證據留言、Counterpart 的跨 repo 對應單留言、關單，以及移除 worktree、刪本機與 `origin` 分支（`push origin --delete`）等收尾，這些都在 wrapper 底下跑、不再詢問（#131）。清單在 `scripts/check-coordinator-permissions.mjs`，`bin/check` 檢查每支都有放行規則，加新腳本時改那份清單、這一條與 allow。`gh pr merge` 會繞過 CI，不放行；wrapper 以外直接跑的跨 repo 寫入（`gh … --repo`）不放行；其他 git 寫入照 ADAPTER.md 的預設，每次都詢問。

- **Requests.** Probe 印出 `REQUEST` 時跑 `node scripts/pilot-request.mjs <主 checkout> list` 取得行號，處理完用 `node scripts/pilot-request.mjs <主 checkout> apply <行號> [--note <備註>]` 或 `decline <行號> --reason <原因>` 標記，不手寫 `applied`／`declined`。請求要合入沒有 Issue 的請求分支（`retro/<x>`）時，用請求的行號當 key，在主 checkout 用 Bash `timeout: 600000` 跑 `node scripts/pilot-land.mjs req-<行號> --branch retro/<x>`：它開出 `.scratch/pilot/batch-req-<行號>.md`（唯一的成員列 Issue 欄是 `-`，格式見 PILOT-STORE.md），之後 Stage、Regression、hold、Integrate 與結果行都照 Stage 到 Integrate 各條目，重跑同一行（帶不帶 `--branch` 都可以）從中斷處接著做；分支不存在印 `STOP branch …`，checkpoint 已有別的分支印 `STOP checkpoint …`。不要再手打 `switch -C pilot/stage-<x>`、`merge --no-ff`、`bin/check --upstream`、`merge --ff-only`、`branch -d`（請求 9、10 的做法沒留下 `regression:` 行，#143）。合入後照 Push gate 推上去（PR body 列這個 batch 的 staged SHA 與 Regression 結果，沒有 `Closes`），Close 對這個成員只清理 terminal、worktree、本機與 `origin` 的分支，再標記 `apply`；成員列沒有 handle，Close 會直接移除這個分支的 worktree，請求來源 session 還開著那個 worktree 時先請它結束。

- **Gates.** `gates.md` 不手改。開 gate 用 `node scripts/pilot-gate.mjs <主 checkout> open --title <標題> --issue <Issue 或 batch> --question <問題> --options <選項> --default <預設> --parked <擱置的項目>`（自動編號 `G<n>`、寫 `opened`，印 `GATE_OPENED G<n>`）；人回覆後用 `node scripts/pilot-gate.mjs <主 checkout> resolve G<n> --how <怎麼解、回覆在哪>` 解除（印 `GATE_RESOLVED G<n>`；`STOP G<n> resolved`、`STOP G<n> missing` 是已經解過或沒有這個 gate，檔案不動，先跑 `list` 對照）；`list` 列出開著的 gate，與 Probe 的 `GATE`、`GATE_MALFORMED` 行相同。gate 擋住的是之後所有 push（例如 GitHub Actions 帳務）而不只點名的 batch 時，`--parked` 以固定寫法 `all-push` 開頭（後面可加說明，如 `all-push（帳務恢復前）`），Probe 才會把各 batch 的 `RESUME_PUSH`、`NOT_IN_MAIN` 收成一行 `PUSH_PARKED`（#136）。依先例直接套用預設、不等人時，照樣先 `open` 留下紀錄，再用印出的 `G<n>` 立刻 `resolve`。欄位都是一行，`--how` 不能有 `|`。gate 要人改某個 worktree 裡的檔案（例如在成員的 `.claude/settings.json` 加 allow）時，`--question` 寫出檔案的絕對路徑，並附人可以直接用 `!` 執行的指令（編輯後 `git -C <worktree> commit`）；只寫相對路徑，人會改到主 checkout，Probe 印 `DIRTY` 擋住所有 merge（G10，#171）。

- **Scripts ahead.** Probe 印 `ADAPTER_AHEAD` 那一輪，整合分支 adapter 提到、主 checkout 還沒有的 `scripts/*.mjs`（`main` 上跑會 `MODULE_NOT_FOUND`），一律在主 checkout 以 `node <stage worktree>/scripts/<x>.mjs …` 執行，不必讀腳本確認：pilot 腳本以 cwd 的 `git worktree list` 第一行當主 checkout，從主 checkout 跑就對（#138）。Push gate 的 `pilot-pr-body.mjs` 與 `pilot-land.mjs sync-main` 不看這一條，每次都照 Push gate 跑 stage worktree 的版本（#239：`main` 已有、但比整合分支舊的腳本不會 `MODULE_NOT_FOUND`，只會誤判）。

- **Scope supplement.** Dispatch 之後要補範圍時，先在 Issue 留言（worker 以 Issue 為依據），再在主 checkout 跑 `node scripts/orca-session-send.mjs --terminal <handle> --prompt <提醒> --queue` 送提醒：它不等 worker 閒置，印 `QUEUED <handle>` 表示提醒已排進下一輪，`STOP <原因>` 時留言仍在，回報人（不加 `--queue` 會等 tui-idle，worker 一直在跑就逾時，#133）。Drain 到這個成員的 `DONE` 時，核對它的分支有沒有帶進補充的內容，沒有就回報人。

- **Probe lines.** Probe 條目沒處理的行，各行與處理：`ADAPTER_AHEAD <檔案> [<名稱>,…]` 是 `pilot/integration` 上的 adapter 比 `main` 新（整合分支有這個檔、內容不同，而且 `main` 最後一次改它的 commit 已在整合分支裡；兩邊都改過時不印；下一批在整合分支上 stage，#52），這一輪改讀 `git -C <主 checkout> show pilot/integration:<檔案>` 的版本，不讀整份 diff（Close 條目單行約 3 KB，diff 會被截斷，#144）：檔名後面附了名稱（依名稱排序、以 `,` 分隔，名稱本身可能有空格，條目名稱不要用 `,`）就只讀那幾個 `- **<名稱>.**` 條目（每個名稱跑一次 `git -C <主 checkout> show pilot/integration:<檔案> | awk -v n='- **<名稱>.**' 'p&&/^[^ \t]/{exit} index($0,n)==1{p=1} p'`，從條目那一行讀到下一個不縮排的非空行為止，中間的空行與 Push gate 那樣的縮排續行都在內，條目之間沒有空行分隔也不會多讀，同 `pilot-probe.mjs` 認定條目的範圍），讀不到的名稱是整合分支刪掉或改名前的條目；沒附名稱表示有條目以外的改動，讀整份；`GATE_MALFORMED <id> <行>` 是把 resolved 寫進別的欄位（如 `- status：resolved …`）的 gate，probe 仍當它開著，照 Gates 用 `resolve` 補上正確的 resolved 行；`DEPS_PROSE <n> #<m>` 是開著的 `ready-for-agent` Issue 內文寫了「依賴 #m」或先後寫法（「排在 #m 之後」「以 #m 為 blocker」「等 #m 合入」，寫成「它們」「這些」「上述」時指同一句前面的號碼；單數的「它」、「不必等」這類否定不算），#m 還開著，`blocked_by` 卻沒有它（Pool 只讀 `blocked_by`，會把 #n 跟 #m 同時派出，#94；#166 只寫「以它們為 blocker，最後做」，#206）：先讀那句確認說的是 #n 自己要等 #m（不是別張單或之後的子單），是才照 [issue-tracker.md](issue-tracker.md#wayfinding-operations) 的 Blocking 跑 `node scripts/gh-tracker.mjs blocked-by add <n> <m>`，再列 Pool 挑單（#n 這時進 `blocked` 桶，#m 關閉後才回到池子），不是就照常挑；`DEPS_PROSE <n> last ok` 與 `DEPS_PROSE <n> last new #<m> [#<k>…]` 是內文寫「最後做」卻沒號碼：`last ok` 表示沒有比 `blocked_by` 最新一張（空時比 #n 自己）還新、開著、不在 `blocked_by` 的單（`retro-candidates`、母單與 `blocked_by` 已有 #n 的單不算，後者再加會成環），不必處理；`last new` 列出這種新單（#228：判斷過之後 `/retro-collect` 又開了 #221，#166 沒掛它），逐張讀它改的檔或條目，#n 要等的（通常是改同一個檔或條目的）照同一條 Blocking 加上，不必等的不加、照常挑（已判斷不加的新單之後每輪仍會列出，同一張不必重判）；`DEPS_PROSE_FAILED <錯誤>`（在主 checkout 跑 `gh` 失敗，這一輪的 PARENT_* 也沒檢查）回報人；`APPLY_MISS <key> <n> rows <列數>`（對不到唯一一列 running 的成員列，沒寫檔）與 `APPLY_MISS <key> <n|current> verify`（寫回後再讀沒對上）會讓腳本 exit 1：照這一行回報人、不手改，這一輪不 stage、不 merge，不必照 Probe 條目 exit 非 0 的做法跑 Bare guard（stderr 是空的），`RESTAGE <key> regression-failed <code 或 none>`（`current: staged` 的 batch，最後一行 `regression:` 不是 staged SHA 的 `exit 0`；`none` 是沒有這行、SHA 是先前那次 stage 的或沒寫 exit。#191：batch 94 兩次 Regression 都 exit 1 停在 staged，probe 什麼都不印，接手的 coordinator 漏掉它）：`none` 也可能是 `pilot-land.mjs` 已寫 `staged`、Regression 還在跑（兩者之間沒有鎖），先確認沒有別的 session 正在跑這個 key 的 `pilot-land.mjs`，有就等它結束、下一輪再看；接著讀 `<主 checkout>/.scratch/pilot/reg-<key>.log`，並數 batch checkpoint 裡失敗的 `regression:` 行：是負載造成的 flake（計時測試在高負載下失敗），而且這個 key 還沒有連續兩次（不同 staged SHA）失敗，就用 Bash `timeout: 600000` 重跑 `node scripts/pilot-land.mjs <key>`（它重新 stage、重跑 Regression；負載還高時照 Stage 的 load 門檻（#178）印 `STOP load`，下一輪再跑）；同一個 key 已經連續兩次（不同 staged SHA）失敗，或不是 flake，照 Regression 修好原因或開 gate；`current:` 是 `merged <sha>` 或 `pushed <sha>` 的 batch：`IN_MAIN` 做 Close（`merged` 已由 `--apply` 改成 `pushed`）；`RESUME_PUSH` 是 Integrate 之後、Push gate 做完之前中斷的 `merged` batch（`pilot/integration` 的 tip 等於最後一次 Regression SHA，且那一行是 exit 0，#37、#130），從 Push gate 第 1 步接著做，PR 已經開著時第 1 步會先更新 body、`land.mjs` 沿用它從等 CI、合併那步接著做；`NOT_IN_MAIN <key>` 是還沒進 `origin/main` 的 `pushed` batch（`--apply` 只在 merge 進了 `origin/main` 之後才寫 `pushed`，所以只有舊格式或之後被 revert 才會出現），重跑 Push gate（`land.mjs` 每一步都能從中斷處接著做）；`NOT_IN_MAIN <key> no-sha`、`NOT_IN_MAIN <key> no-regression`（`merged` 卻沒有 `regression:` 行，或它的 SHA 解析不到）、`NOT_IN_MAIN <key> regression-failed <code 或 none>`（`merged` 但最後一行 `regression:` 的 SHA 後面不是 `exit 0`，Regression 沒通過的內容不能推，#130）、`NOT_IN_MAIN <key> tip <sha 或 none>`（`merged` 但 `pilot/integration` 的 tip 不是 Regression SHA，直接推會送出沒驗過的內容）與 `FETCH_FAILED` 回報人；`PUSH_PARKED <gate id> <batch 數> batches` 是開著的 gate 的 parked 寫了 `all-push`（見 Gates），上面所有 `RESUME_PUSH`、`NOT_IN_MAIN` 行（`no-sha`、`no-regression`、`regression-failed`、`tip` 也在內）都收成這一行（#136）：不做 Push gate、不重跑，等那個 gate 解除；解除後的下一輪恢復各行，要回報人的照上面回報。母單（[issue-tracker.md](issue-tracker.md#母單)）由腳本整理，不再手動跑關係總覽（#164：寫在條目尾端的手動步驟好幾輪都被 stage 與 land 擠掉）：`PARENT_LABEL <n>`（開著、有 sub-issue，或已關閉卻有開著子單的母單，沒有 `parent` label 或還掛 triage label）與 `PARENT_REOPEN <n>`（開著的子單指向已關閉的母單 #n，新掛上或子單被重開）已由 `--apply` 經 `scripts/gh-tracker.mjs` 補上 `parent`、移除 triage label 或重開，不必再做；`PARENT_APPLY_FAILED <n> <錯誤>`（寫入失敗，腳本 exit 1，其他母單照修）回報人，不在 wrapper 外手動重跑。
