# Pilot：少見的分支

[pilot.md](pilot.md) 的 pointer 指到這裡時才讀，每條只在 pointer 寫的情況用到。下文的 `<主 checkout>`、`<stage worktree>` 與其他條目名稱都指 pilot.md 的同名條目。

- **Bare guard.** Orca 從 WSL 做 worktree 操作（create、rm 都會）時，可能把主 checkout `.git/config` 的 `core.bare` 改成 `true`，之後 `git status` 回 `must be run in a work tree`，stage、merge 全部失敗。在主 checkout 跑 `scripts/pilot-unbare.sh <主 checkout> <時機>`（setup-workflow 正本的副本，hook 版是 `scripts/claude-hook-unbare.sh`）（時機如 `probe`、`dispatch #<n>`、`stage #<key>`、`close #<n>`）：是 bare 就執行 `git config core.bare false`、在 `.scratch/pilot/decisions.md` 的表格追加一列，並印出 `UNBARE <checkout>`；不是 bare 時不輸出。下列 Probe、Dispatch、Stage、Close 都只呼叫它。主 checkout 的工作樹還沒有這支腳本時（本機 `main` 落後 `origin/main`），改跑 `git -C <主 checkout> rev-parse --is-bare-repository`，印出 `true` 就執行 `git -C <主 checkout> config core.bare false`，再照 Decisions 記一列。

- **Dispatch stops.** [pilot.md](pilot.md) 的 Dispatch 印 `STOP` 或 `WARN release` 時的處理。認領之後 `pilot-dispatch.mjs` 對成員印 `STOP <n> …`（`not-claimed`、`send` 除外）、這個成員不再重派時，用 `node scripts/gh-tracker.mjs edit <n> --remove-assignee @me` 放掉認領，免得其他機器要等它變成 `stale`。`STOP capacity` 時腳本已放掉這個 session 認領的成員（`RELEASED <n>`）；stderr 印 `WARN release <n> edit …` 的成員才手動用 `node scripts/gh-tracker.mjs edit <n> --remove-assignee @me` 放掉，`WARN release <n> claim-check …` 先照 claim 確認認領者。`STOP orca-unavailable <第一行>`（exit 4，不屬於任何成員，#394）：派工前的 `"$ORCA_CLI_COMMAND" worktree list --json` 失敗，Orca CLI 整個不能用，腳本什麼都沒建、沒寫 checkpoint：不放掉認領、不另查 git，下一輪用同一個 key 與成員原樣重跑（#391：Orca 約 20 分鐘後恢復）。`STOP <n> worktree-branch <路徑> <分支>`（成員行記 `stop`）：`git worktree list` 已有目錄名 `issue-<n>`、分支卻不同名的舊 worktree，Orca 只會去重出 `issue-<n>-2`；把那個分支（detached 時先在那裡開出）改名成 `issue/<n>-<slug>` 後用同一個 key 只帶它重跑，接著舊分支做。`STOP <n> not-claimed` 照 claim 的 `STOP <n> claimed …` 處理：先跑 claim 看是誰，別的機器或 session 在做就從這一批拿掉、不放掉指派（同一個帳號，`--remove-assignee @me` 會拿掉對方的），`CLAIMED` 了才用同一個 key 只帶它重跑；`STOP <n> claim-check …` 是讀不到 Issue 留言，修好 gh 後重跑。認領之後、開 worktree 之前，成員本機已有分支（重跑）時，腳本照 Probe 的 `OVERLAP` 同一套比法（`pilot-probe.mjs` 共用）比對它和開著的 batch 裡其他 `running`、`done` 成員，改到同一個檔或同一個 `- **<名稱>.**` 條目就印 `STOP <n> overlap <m> <檔案>[:<條目>]…`（多個成員以 `, <m> …` 接著列），不關、不開分頁，分支與成員行都不動（比對本身失敗是 `STOP <n> overlap-check …`，成員行記 `stop`，修好 git 後重跑；#174：重派 #94 時 #134 正在改同一個 **Probe.** 條目，之後 stage 衝突整個重做）：用 `node scripts/gh-tracker.mjs blocked-by add <n> <m>`（[issue-tracker.md](issue-tracker.md#wayfinding-operations)）讓後做的 #n 等 #m 合入，放掉 #n 的認領，從這一批拿掉；只有兩邊確定不會衝突（例如 #m 已確定不合入）時才加 `--allow-overlap` 重跑。還沒派過的成員沒有分支可比。STOP 的成員修好原因後用同一個 key 只帶它重跑（worktree 已在就不再 create，先關掉 worktree 裡每個舊分頁再開新的，不必再從 checkpoint 撈 handle 手動 `terminal close`；成員行還是 `running`、它的分頁也還開著時印 `STOP <n> running <handle>`，什麼都不動，表示 worker 還在跑，重跑只帶 STOP 的成員）；`create` 開頭的 STOP 先到 Orca 查 worktree 是不是還在背景建立，不要直接重跑。`STOP <n> terminal selector_not_found`：腳本已等 Orca 列出新 worktree 並重試過一次 `terminal create`，仍找不到才停；先確認 `"$ORCA_CLI_COMMAND" worktree list --json` 列出它，再用同一個 key 只帶它重跑。`STOP <n> send <handle>`（成員行記 `running`，#354）：確認不了不代表 worker 沒收到，可能已在跑；不放掉認領、不重派、不手動補送（會再排進佇列），交給 Probe：之後印結果行就照常處理，超過 stuck-after 仍沒動靜時 `WORKER <n> STUCK` 再回報人。

- **Permissions.** `.claude/settings.json` 的 `permissions.allow` 有三條，每條都是本 repo 的 wrapper（規則比對 `node scripts/<name>` 這個相對路徑）、只做 adapter 指定的步驟，auto mode 才不會擋成 External System Writes：`Bash(node scripts/gh-tracker.mjs:*)`，本 repo 的留言、label、關單、開單、sub-issue 與依賴都經這支（[issue-tracker.md](issue-tracker.md)，#96）；`Bash(node scripts/land.mjs:*)`，Push gate 與單獨跑的 `/issue-run` 落地時 push、開 PR、等 CI 通過後才合併（[Evidence and closing](issue-run.md#evidence-and-closing)）；`Bash(node scripts/pilot-close.mjs:*)`，Close 的證據留言、Counterpart 的跨 repo 對應單留言、關單，以及移除 worktree、刪本機與 `origin` 分支（`push origin --delete`）等收尾，這些都在 wrapper 底下跑、不再詢問（#131）。本 repo 在 setup-workflow L3 的 push 那一題答是，所以 `bin/check` 跑 `node scripts/check-coordinator-permissions.mjs --push`，檢查三條都在（答否的 repo 不帶 `--push`，有 land、close 規則反而失敗）；它和 `gh-tracker.mjs` 都是 setup-workflow 正本的副本（#244），清單要加腳本時改正本、照 [issue-run.md](issue-run.md#checks) 重新複製，再改這一條與 allow。`gh pr merge` 會繞過 CI，不放行；wrapper 以外直接跑的跨 repo 寫入（`gh … --repo`）不放行；其他 git 寫入照 ADAPTER.md 的預設，每次都詢問。

- **Requests.** Probe 印出 `REQUEST` 時跑 `node scripts/pilot-request.mjs <主 checkout> list` 取得行號，處理完用 `node scripts/pilot-request.mjs <主 checkout> apply <行號> [--note <備註>]` 或 `decline <行號> --reason <原因>` 標記，不手寫 `applied`／`declined`。請求要合入沒有 Issue 的請求分支（`retro/<x>`）時，用請求的行號當 key，在主 checkout 用 Bash `timeout: 600000` 跑 `node scripts/pilot-land.mjs req-<行號> --branch retro/<x> --check-command 'bin/check --upstream' --resolver scripts/pilot-resolve.mjs`：它開出 `.scratch/pilot/batch-req-<行號>.md`（唯一的成員列 Issue 欄是 `-`，格式見 PILOT-STORE.md），之後 Stage、Regression、hold、Integrate 與結果行都照 Stage 到 Integrate 各條目，重跑同一行（帶不帶 `--branch` 都可以）從中斷處接著做；分支不存在印 `STOP branch …`，checkpoint 已有別的分支印 `STOP checkpoint …`。不要再手打 `switch -C pilot/stage-<x>`、`merge --no-ff`、`bin/check --upstream`、`merge --ff-only`、`branch -d`（請求 9、10 的做法沒留下 `regression:` 行，#143）。合入後照 Push gate 推上去（PR body 列這個 batch 的 staged SHA 與 Regression 結果，沒有 `Closes`），Close 對這個成員只清理 terminal、worktree、本機與 `origin` 的分支，再標記 `apply`；成員列沒有 handle，Close 會直接移除這個分支的 worktree，請求來源 session 還開著那個 worktree 時先請它結束。

- **Gates.** `gates.md` 不手改。開 gate 用 `node scripts/pilot-gate.mjs <主 checkout> open --title <標題> --issue <Issue 或 batch> --question <問題> --options <選項> --default <預設> --parked <擱置的項目> [--hold <n>] [--script <步驟檔>]`（要人執行指令的 gate 帶 `--script`，見下文；gate 擋住的是某個 batch 成員 #n 時帶 `--hold <n>`（段落多一個 `- hold：#<n>`）：gate 解除前 Probe 對 done 的 #n 印 `HELD <n> G<k>`、不印那個 batch 的 `STAGEABLE`，`pilot-land.mjs` 印 `STOP held <n> G<k>`、什麼都不動；`resolve` 之後下一輪照常 stage（#367：investing#320 等 G28 時 Probe 仍印 `STAGEABLE 320`）；自動編號 `G<n>`、寫 `opened`，印 `GATE_OPENED G<n>`）；人回覆後用 `node scripts/pilot-gate.mjs <主 checkout> resolve G<n> --how <怎麼解、回覆在哪>` 解除（印 `GATE_RESOLVED G<n>`；`STOP G<n> resolved`、`STOP G<n> missing` 是已經解過或沒有這個 gate，檔案不動，先跑 `list` 對照）；`list` 列出開著的 gate，與 Probe 的 `GATE`、`GATE_MALFORMED` 行相同。gate 擋住的是之後所有 push（例如 GitHub Actions 帳務）而不只點名的 batch 時，`--parked` 以固定寫法 `all-push` 開頭（後面可加說明，如 `all-push（帳務恢復前）`），Probe 才會把各 batch 的 `RESUME_PUSH`、`NOT_IN_MAIN` 收成一行 `PUSH_PARKED`（#136）。依先例直接套用預設、不等人時，照樣先 `open` 留下紀錄，再用印出的 `G<n>` 立刻 `resolve`。欄位都是一行，`--how` 不能有 `|`。要人執行指令（合入 PR、提交 ADR、留言等）的 gate，把步驟寫成檔案、`open` 加 `--script <檔>`：它產生 `.scratch/pilot/gates/G<n>.sh`（印 `GATE_SCRIPT <路徑>`，段落多一個 `- script：` 欄位），交接與清 session 暫存區後還在；開 gate 前還不知道 `G<n>`，`--question` 不寫路徑，`open` 會在尾端補上 ` 執行：! bash .scratch/pilot/gates/G<n>.sh`（在主 checkout 執行；zsh 也可以；腳本開頭會回到主 checkout 根目錄，步驟裡 cd 到別處也不影響完成標記）。步驟每一步先寫 `step <說明>`；只讀狀態的查詢寫成 `x="$(<指令>)" || true` 再自己判斷輸出，不然查詢回非零（例如 `main-pr.py status` 未就緒回 1）就會停；改狀態的步驟（commit、update-ref、留言、合入）先查狀態、已做過就跳過，中途失敗重跑才不會重做。任一步失敗時 stderr 印 `停止：第 <行> 行失敗（步驟：<說明>）`，人修好原因後重跑同一條指令會從頭執行；跑完寫 `G<n>.done`、印 `GATE_SCRIPT_DONE G<n>`，之後再跑不重做（#325 第 5 項：G16 裸 `set -e` 遇查詢回 1 時什麼都沒印就結束；G10 的腳本放在 session 暫存區，交接後就不見；#371）。gate 要人改某個 worktree 裡的檔案（例如在成員的 `.claude/settings.json` 加 allow）時，`--question` 寫出檔案的絕對路徑；要人執行的指令照上面寫成 `--script` 的步驟（編輯後 `git -C <worktree> commit`）；只寫相對路徑，人會改到主 checkout，Probe 印 `DIRTY` 擋住所有 merge（G10，#171）。產品決定的 gate 擋住某張 Issue 時：那張 Issue 是開著的 batch 的成員就在 `open` 帶 `--hold <n>`（investing#320 等 G28 時沒帶，Probe 照印 `STAGEABLE 320`，#367）；`open` 之後把該 Issue 的 `ready-for-agent` 換成 `ready-for-human`（`node scripts/gh-tracker.mjs edit <n> --add-label ready-for-human --remove-label ready-for-agent`）；人回覆後依序 `resolve G<n>`、把決定以 AI 聲明開頭留言到該 Issue（`node scripts/gh-tracker.mjs comment <n> --body-file <檔>`，worker 只讀 Issue）、label 換回 `ready-for-agent`、跑 Probe（`--apply` 把 STOP 的成員記成 parked 或印 `PARKED`）、`node scripts/issue-pool.mjs claim <n>`，再照 Dispatch 重派（#269：G20 解除後 coordinator 自己湊出這 6 步）。

- **Scripts ahead.** Probe 印 `ADAPTER_AHEAD` 那一輪，整合分支 adapter 提到、主 checkout 還沒有或內容與整合分支不同的 `scripts/*`（`main` 上跑會 `MODULE_NOT_FOUND`，舊版則可能靜默做錯：investing 舊版 `pilot-watch.mjs` 帶多個 `--batch` 只看最後一個、`campaign-due.py` 讀不懂新欄位，#358），Probe 各印一行 `SCRIPT_AHEAD <路徑> run-in <stage worktree>`（含 `.py`、`.sh`），一律在主 checkout 以 `node <stage worktree>/<路徑> …`（`.py` 用 `python3`）執行，不必讀腳本確認；印 `SCRIPT_AHEAD <路徑> sync-main` 時 stage worktree 不存在或也沒有這個檔，先照 [pilot.md](pilot.md) 的 Integration branch 跑 `pilot-land.mjs sync-main`，下一輪 Probe 改印 `run-in` 再跑：pilot 腳本以 cwd 的 `git worktree list` 第一行當主 checkout，從主 checkout 跑就對（#138）。主 checkout 已有、但不認得整合分支 adapter 指令帶的旗標（印用法、exit 2；#245 的 `pilot-land.mjs` 的 `--check-command`、`--resolver` 在合進 `main` 之前就是這樣）的腳本也一樣改跑 `<stage worktree>/scripts/` 的版本，`--resolver` 的相對路徑跟著指到 stage worktree 的 `scripts/pilot-resolve.mjs`。Push gate 的 `pilot-pr-body.mjs` 與 `pilot-land.mjs sync-main` 不看這一條，從主 checkout 的入口跑就會自己轉到 stage worktree 的版本（#275；#239：`main` 已有、但比整合分支舊的腳本不會 `MODULE_NOT_FOUND`，只會誤判）。

- **Scope supplement.** Dispatch 之後要補範圍時，先在 Issue 留言（worker 以 Issue 為依據），再在主 checkout 跑 `node scripts/orca-session-send.mjs --terminal <handle> --prompt <提醒> --queue` 送提醒：它不等 worker 閒置，印 `QUEUED <handle>` 表示提醒已排進下一輪，`STOP <原因>` 時留言仍在，回報人（不加 `--queue` 會等 tui-idle，worker 一直在跑就逾時，#133）。Drain 到這個成員的 `DONE` 時，核對它的分支有沒有帶進補充的內容，沒有就回報人。

- **Regression.** `pilot-land.mjs` 在 `<stage worktree>` 的 staged SHA、工作樹乾淨時跑 `<stage worktree>/bin/check --upstream`，exit 0 才算過；只對那個 SHA 有效。完整輸出在 `<主 checkout>/.scratch/pilot/reg-<key>.log`，結果追加成 `regression: <sha> exit <code>`，通過時後面附 `bin/check` 最後一行 `CHECK_PASS tests <a>+<b>+<c>`（各組測試的數目：tests、setup-workflow 正本、以 macOS 樣本重跑用到假 Orca 的測試；只看尾段的 `ℹ tests` 會只拿到最後一組）。沒過印 `STOP regression <exit>`，`pilot/integration` 不動：讀 log 找原因，修好後重跑同一行指令，它會重新 stage、重跑；失敗只歸因於某個成員時見 [pilot-conflict.md](pilot-conflict.md) 的 Fresh redispatch。

- **Integrate.** `pilot-land.mjs` 在 Regression 通過後先看 hold flag，存在就印 `STOP hold`；再比對 `pilot/integration` 現在的 tip 和 `current:` 記下的 `onto <tip>`，不同就印 `STOP drift`：stage 之後整合分支前進了，這個組合沒驗過。比的是 stage 當下記的 tip，不數 parent（batch-40-51 用 `$SHA^1` 誤判兩個成員的 batch），也不是 dispatch 時 `integration:` 行的 SHA（Push gate 的 `land.mjs` 會把 `pilot/integration` 推進到 PR 的 merge commit）。兩種 STOP 都不動 `pilot/integration`，下一輪重跑同一行指令：tip、成員組合與各成員分支都沒變、staged SHA 的 Regression 已經通過時直接從這一步繼續（印 `RESUME <key> <sha>`，不重跑 Regression），tip 變了就從新的 tip 重新 stage。都沒有才在 `<stage worktree>` 切回 `pilot/integration`、`merge --ff-only pilot/stage-<key>`、`branch -d pilot/stage-<key>`，把 `current:` 寫成 `merged <sha>`，最後一行印 `MERGED <key> <sha>`（已經 `merged` 時重跑只再印一次）。checkpoint 寫回後腳本會再讀一次，沒寫進去就印 `STOP checkpoint …`。stage worktree 停在 `pilot/integration` 等下一批，不移除。exit 0 是 `MERGED`、4 是 STOP、2 是用法錯誤。
