# Pilot：Retro collect

`/retro-collect` 讀的專案事實；coordinator 用不到。[pilot.md](pilot.md) 留一行 pointer，`/retro` 以那條判斷要不要進收集模式。

- **Retro collect.** `/retro-collect` 在主 checkout 跑，把開著的 `retro-candidates` Issue 做成一個 retro 單位；`<key>` 是 `<MMDD><字母>`，和計畫檔 `.scratch/retro/plan-<key>.md` 同名；字母取下面三處都沒用過的下一個：`git fetch` 後的 `git log --oneline origin/main | grep -o 'retro <MMDD>[a-z]'`、`git branch -a --list '*retro/<MMDD>*'`、主 checkout 的 `ls .scratch/retro/plan-<MMDD>*`（別台機器或已清掉計畫檔的 retro 只在前兩處看得到，#253：`.scratch/retro/` 只有 `plan-1101a.md`，`main` 上已有 `chore: retro 1101b`）。認領：在主 checkout 對每張跑 `node scripts/issue-pool.mjs claim <n>`，印 `CLAIMED <n>` 才收，`STOP <n> claimed …` 表示別的 session 在收、這次略過；STOP 前多印 `STALE_CLAIM <n> <認領者> <最後活動>` 時，認領者是本機已一小時沒寫 transcript 的 session，改跑 `node scripts/issue-pool.mjs claim <n> --take-stale` 接手（印 `CLAIMED <n> stale <session>`），報告寫出認領者與最後活動（#212）。目標分支是 `main`。worktree：設了 `ORCA_CLI_COMMAND` 時 `node scripts/orca-worktree-create.mjs --name retro-<key> --base-branch main --branch retro/<key>`（看最後一行 JSON 的 `path`），沒有 Orca 時 `git worktree add -b retro/<key> <路徑> main`。計畫檔寫在主 checkout，不寫在 retro worktree：`land.mjs` 移除 worktree 時會一起刪掉（#170）。改到 `scripts/workflow-doc-sync.json` 列出的來源（各 skill 的 `SKILL.md`、`ADAPTER.md` 等）時，commit 前先跑 `node scripts/check-workflow-sync.mjs`（幾秒）；印 `WORKFLOW_SYNC_STALE <來源>` 時先對照 `docs/workflow/` 的對應章節更新、跑 `node scripts/build-workflow-site.mjs` 與 `node scripts/check-workflow-sync.mjs --restamp`，再跑 `bin/check`（#224：第一次 `bin/check` 約 50 秒後才報 STALE，多跑一整輪）。改到 `docs/agents/workflow-templates.json` 列出的副本（`scripts/` 裡從 setup-workflow 正本複製來的檔）時照 [issue-run.md](issue-run.md) 開頭的副本規則：改正本、`git add` 後跑 `copy-templates.mjs . --no-tests --yes --staged <名稱>`，不手動 `cp`、不手算 sha256（#250：第三次手動 cp，`bin/check` 才報 sha256 不符）。合入前重查並行改動在 retro worktree 跑 `node scripts/worktree-overlap.mjs --mine`。檢查：開發中用 Bash 的 `run_in_background` 跑 `bin/check`（整條超過預設的 120 秒，#212；完整的 `bin/check` 自己先排全機 heavy-slot，排隊加執行可能超過 `timeout: 600000` 的十分鐘，exit 75 是沒排到 slot、稍後重跑，item 138）；tip 上的 `bin/check --upstream` 由 CI 跑（`land.mjs` 會等它），restamp 之後的那一次由下面 land 指令的 `--check-command` 涵蓋。commit 用 `git add -A`：`.scratch` 已在 `.gitignore`，再加 `':!.scratch'` 排除會讓 git 印 ignored 提示並 exit 1，`&&` 後面的 commit 不會跑（#170）。合入與 push 照 [Evidence and closing](issue-run.md#evidence-and-closing) 單獨跑的方式：PR body 每張收集的 Issue 一行 `Closes #<n>`，用 Bash `timeout: 600000` 跑 `node scripts/land.mjs retro/<key> --title 'chore: retro <key>' --body-file <檔> --check-command 'bin/check --upstream'`（不帶時 restamp 之後跑的是沒有 `--upstream` 的 `bin/check`，和 Delivery 的交付指令不一致，#235），結果行的處理也照那一段。

- **Retro trigger.** `Retro trigger: count=5 age=8h`（CoS item 41，owner 2026-11-20 核准）。issue-pilot 每個 tick 的第 4 步 Retro trigger（Project tick hooks 是「沒有」也照做，CoS item 89）讀 Probe 印的 `RETRO_` 行（Probe 內部跑 `node scripts/pilot-retro-due.mjs <主 checkout>` 的判斷；Probe 沒印時才在主 checkout 自己跑它）；`RETRO_DUE` 時跑它箭頭後的指令（在主 checkout 開新分頁打 `/retro-collect`，印 `RETRO_STARTED <handle>`，腳本自己在 `.scratch/retro/triggers.log` 追加一行 JSON、經 `pilot-decision.mjs` 在 `decisions.md` 記一列），其他結果行照 issue-pilot SKILL 第 4 步處理；手動開的收集者（標題沒有狀態前綴）由主 checkout 4 小時內改過、還沒有報告的 `plan-<key>.md` 認出，印 `RETRO_RUNNING plan-<key>`。`/retro-collect` 結束時跑 `node scripts/pilot-retro-due.mjs <主 checkout> --log-collect <key> --item '#<n>=<結果>'…`，同一個 log 追加收集結果；要查自動觸發有沒有接上，讀這個 log。收集報告的否決段落在主 checkout 的 `.scratch/retro/reports/<YYYY-MM-DD>-<key>.md`。

- **Tab sweep.** （CoS item 91 D、item 153，A2）issue-pilot 每個 tick 第 4 步的 Tab sweep（Retro trigger 之後）在主 checkout 跑 `node scripts/tab-sweep.mjs <主 checkout>`（ron-skills 不宣告 roster，不帶 `--roster`：`/retro` 已把候選開成 `retro-candidates` Issue 才換待關閉）。它只動主 checkout 裡標題（tab-state 的前綴）是 `待 Retro｜` 或 `待關閉｜`、`lastOutputAt` 已 10 分鐘以上、畫面閒置（沒有 `esc to interrupt`、沒有 spinner 或 `…ing…` 行、沒有草稿、有一行空的 `❯`）的分頁：待 Retro 送一次 `/retro`、待關閉關分頁；自己、現任 coordinator（`sessions.md` 最後的交接目標）與其他 worktree 的分頁一律不動，兩個都認不出來時整輪不動。結果行照 issue-pilot SKILL 第 4 步處理；動作、失敗、看不清楚而跳過的分頁與每輪的 `SUMMARY` 由腳本自己記進 `decisions.md`（全是 `TAB_SKIP` 也記，`TAB_SWEEP_OFF` 也記一列，#646）；有一列沒記到時腳本最後多印 `TAB_RECORD_FAILED <exit> <錯誤>`、exit 1，同 `TAB_FAILED` 下一輪重試、不開 gate，當輪由 coordinator 用 `pilot-decision.mjs` 補記該輪最後的結果列（`SUMMARY`、`TAB_SWEEP_OFF` 或 `TAB_SWEEP_FAILED`）；被通知叫醒的那一輪與交接後第一輪也要跑。每小時看守不再代清分頁，只核對 coordinator 有沒有做到：coordinator 跑過的每一輪都有一列 Tab sweep 的 `SUMMARY`（或 `TAB_SWEEP_OFF`、`TAB_SWEEP_FAILED`），有 tick 卻沒有這一列就是那一輪沒跑；Idle wait 期間沒有 tick，沒有列不算漏跑。用量吃緊時人把 `.scratch/pilot/tab-sweep.json` 的 `"enabled"` 改成 `false`（印 `TAB_SWEEP_OFF`），coordinator 不改回來。
