# Pilot：Retro collect

`/retro-collect` 讀的專案事實；coordinator 用不到。[pilot.md](pilot.md) 留一行 pointer，`/retro` 以那條判斷要不要進收集模式。

- **Retro collect.** `/retro-collect` 在主 checkout 跑，把開著的 `retro-candidates` Issue 做成一個 retro 單位；`<key>` 是 `<MMDD><字母>`，和計畫檔 `.scratch/retro/plan-<key>.md` 同名。認領：在主 checkout 對每張跑 `node scripts/issue-pool.mjs claim <n>`，印 `CLAIMED <n>` 才收，`STOP <n> claimed …` 表示別的 session 在收、這次略過；STOP 前多印 `STALE_CLAIM <n> <認領者> <最後活動>` 時，認領者是本機已一小時沒寫 transcript 的 session，改跑 `node scripts/issue-pool.mjs claim <n> --take-stale` 接手（印 `CLAIMED <n> stale <session>`），報告寫出認領者與最後活動（#212）。目標分支是 `main`。worktree：設了 `ORCA_CLI_COMMAND` 時 `node scripts/orca-worktree-create.mjs --name retro-<key> --base-branch main --branch retro/<key>`（看最後一行 JSON 的 `path`），沒有 Orca 時 `git worktree add -b retro/<key> <路徑> main`。計畫檔寫在主 checkout，不寫在 retro worktree：`land.mjs` 移除 worktree 時會一起刪掉（#170）。改到 `scripts/workflow-doc-sync.json` 列出的來源（各 skill 的 `SKILL.md`、`ADAPTER.md` 等）時，commit 前先跑 `node scripts/check-workflow-sync.mjs`（幾秒）；印 `WORKFLOW_SYNC_STALE <來源>` 時先對照 `docs/workflow/` 的對應章節更新、跑 `node scripts/build-workflow-site.mjs` 與 `node scripts/check-workflow-sync.mjs --restamp`，再跑 `bin/check`（#224：第一次 `bin/check` 約 50 秒後才報 STALE，多跑一整輪）。改到 `docs/agents/workflow-templates.json` 列出的副本（`scripts/` 裡從 setup-workflow 正本複製來的檔）時照 [issue-run.md](issue-run.md) 開頭的副本規則：改正本、commit 後跑 `copy-templates.mjs`，不手動 `cp`、不手算 sha256（#250：第三次手動 cp，`bin/check` 才報 sha256 不符）。合入前重查並行改動在 retro worktree 跑 `node scripts/worktree-overlap.mjs --mine`。檢查：開發中用 Bash `timeout: 600000` 跑 `bin/check`（整條超過預設的 120 秒，會被移到背景，#212）；tip 上的 `bin/check --upstream` 由 CI 跑（`land.mjs` 會等它），restamp 之後的那一次由下面 land 指令的 `--check-command` 涵蓋。commit 用 `git add -A`：`.scratch` 已在 `.gitignore`，再加 `':!.scratch'` 排除會讓 git 印 ignored 提示並 exit 1，`&&` 後面的 commit 不會跑（#170）。合入與 push 照 [Evidence and closing](issue-run.md#evidence-and-closing) 單獨跑的方式：PR body 每張收集的 Issue 一行 `Closes #<n>`，用 Bash `timeout: 600000` 跑 `node scripts/land.mjs retro/<key> --title 'chore: retro <key>' --body-file <檔> --check-command 'bin/check --upstream'`（不帶時 restamp 之後跑的是沒有 `--upstream` 的 `bin/check`，和 Delivery 的交付指令不一致，#235），結果行的處理也照那一段。
